# APM (Agent Package Manager)

Global APM project lives in `config/apm/`, deployed to `~/.apm/`. APM reads `apm.yml` there and writes generated state (`.opencode/`, `.github/`, `.cursor/`, `AGENTS.md`, `apm.lock.yaml`, `apm_modules/`, `deployment-receipts/`, `logs/`) next to it. It also writes into the real `~/.config/opencode/`.

Single harness: OpenCode. Every addition goes into `config/apm/apm.yml` by hand and is applied by `apm install` / `apm update`, which also re-runs the lifecycle hooks.

## Edit `apm.yml`, do not scaffold

Always edit `config/apm/apm.yml` directly. Do not run `apm install <pkg>`, `apm mcp install`, `apm init` or `apm marketplace *` to add things: they rewrite the manifest in their own shape and drop the hand-tuned parts (explicit `command`/`args`, `registry: false`, hook ordering).

Apply the edit from `~/.apm`, so the linked manifest is the one APM reads:

```bash
cd ~/.apm
apm install --dry-run        # shows the new dep + MCP servers, writes nothing
apm install                  # deploys skills/agents and configures MCP, runs post-install hooks
apm deps list                # what deployed, to which paths
apm update --yes             # refresh git refs, rewrite apm.lock.yaml, run post-update hooks
```

Commit `config/apm/apm.yml` only. `apm.lock.yaml` is machine-local and regenerated by `apm install`.

## Manifest shape

```yaml
name: opencode-config
targets:
  - opencode

dependencies:
  apm:
    - owner/repo                       # APM package: skills, prompts, agents, hooks
  mcp:
    - name: my-server
      registry: false                  # hand-written entry, not from the registry
      transport: stdio
      command: "mise"
      args: [exec, --, npx, -y, "@scope/pkg"]
      enabled: true
```

A remote server uses `transport: http` plus `url:` instead of `command`/`args`. Local servers always run through `mise exec -- npx -y ...`, so the runtime comes from pinned mise versions, never a global npm install.

## What is linked, what is generated

Linked from this repo into `~/.apm/` (`FLAT_HOME_LIST` in `scripts/initialize.sh`): `apm.yml`, `config.json`, `marketplaces.json`, and the `.apm/` dir (so `~/.apm/.apm/instructions/global.instructions.md` resolves).

Generated, machine-local, **not committed**: everything else. `.gitignore` holds `config/apm/.agents/`, `.opencode/`, `.apm-local/`, `apm_modules/`, `opencode.json`, `.gitignore` itself.

`.apm/instructions/global.instructions.md` is the global instruction text APM compiles into every target's `AGENTS.md`. Edit it here, then re-run `apm install`.

## Adding an OpenCode plugin (lifecycle hooks)

A `plugin` / `plugins` entry in `opencode.json` only loads code. A plugin's skills, agents and commands only land on disk when its install command runs. So every plugin lives in the lifecycle hooks, which is why apm.yml exists here at all.

A new plugin needs an entry in **all three** lists, in the same order:

| List | Command |
| --- | --- |
| `post-install` | install, e.g. `opencode plugin add <pkg>` |
| `post-update` | same command again (plugins do not version-pin) |
| `pre-uninstall` | `opencode plugin remove <pkg>` |

Each entry is `type: command` with a `description`, a `bash` line wrapped in `mise exec --`, and a `timeoutSec` (30–180 is the range in use). Caveman installs differently: `npx -y github:JuliusBrussee/caveman -- --only opencode --all --force`, and uninstalls with `--uninstall --non-interactive`.

Today: caveman, ponytail, `opencode-models-discovery`, superpowers (git URL), rtk (`rtk init --global --opencode` / `--uninstall`).

If a hook aborts, the lockfile is already rewritten and that plugin is half-updated. Re-run `apm install` before committing.

## Verify

```bash
cd ~/.apm
apm install --frozen --dry-run    # manifest and lockfile agree; fetches packages over git
apm targets                       # opencode must be active
apm deps list                     # deployed files under .config/opencode/
git -C ~/Documents/Programming/Projects/dotfiles status --short config/apm
```

`git status` must show only `apm.yml` (and `.apm/instructions/`) after a config change, never generated output.

## Gotchas

- `apm deps list` marks plugin-installed packages `orphaned` when `apm_modules/` holds them but the manifest does not (ponytail, superpowers, caveman, agentmemory today). Never run `apm prune`: it deletes them, and the `pre-uninstall` hooks are the only thing that removes their plugin entries.
- `apm.yml` sets `targets: opencode`, but `apm targets` also reports copilot, cursor, windsurf active because APM auto-detects a target when its deploy dir exists. That is harmless state in `~/.apm/`, not a second harness.
- Do not edit an APM-managed MCP server in `~/.config/opencode/opencode.json`. Edit `apm.yml` and re-install, or the next `apm install` overwrites you.
- `config/apm/config.json` only sets `default_client`. `marketplaces.json` is intentionally empty.
